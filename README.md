# つづく貯金

> がんばった分だけ、貯まっていく。

「続けたいけれど、今日はあまりやりたくない」と感じる行動を達成したときに、自分へのごほうびとして貯金を積み立てる習慣アプリです。

自炊、運動、読書、早起きなどの習慣と、達成したときに貯める金額を登録します。できた項目を毎日タップすると、行動の継続と貯金が同時に積み上がります。

## このアプリについて

運動や自炊、勉強などは「続けた方がよい」と分かっていても、目の前の面倒さに負けてしまいがちです。一方、習慣化アプリで記録するだけでは、行動する理由が弱く、記録自体が続かなくなることがあります。

つづく貯金は、行動の達成に具体的な金額を結び付けることで、この問題を解決します。「運動できたら 300 円」「自炊できたら 500 円」のように、自分で決めた金額を達成のたびに積み立てます。健康や生活習慣が改善されるだけでなく、欲しいものや旅行のためのお金も貯まる、一石二鳥の体験を目指しました。

### 解決したい課題

- 将来のために続けたい行動ほど、今日すぐに得られるメリットを感じにくい
- 習慣管理が「できた・できなかった」の記録だけになり、達成感が薄い
- 完璧な連続記録を求めると、一度休んだだけで継続意欲を失いやすい

### アプローチ

- 達成した行動を金額に変え、成果を分かりやすく可視化する
- 習慣ごとに難易度や節約効果に合った金額を設定できるようにする
- 未達成を失敗として強調せず、できた行動だけを積み上げる
- 合計金額、目標までの進捗、グラフ、カレンダーで成長を振り返れるようにする

```text
少し面倒だけど続けたいことを実行する
                ↓
          達成を記録する
                ↓
           貯金が増える
                ↓
     習慣とお金が一緒に積み上がる
```

## 主な機能

- 自炊・運動・読書・早起きなど、続けたい習慣を複数登録
- 習慣ごとに達成時の貯金額を設定
- その日に達成した習慣をワンタップで記録・取り消し
- 当日の貯金額、累計貯金額、継続日数を表示
- 累計貯金額の推移をグラフで可視化
- カレンダーで日ごとの達成数、貯金額、達成内容を確認
- 欲しいものや旅行などの目標金額を登録
- スマートフォンへ追加できる PWA 対応

## 画面と利用体験

### 初回設定

初めてログインしたユーザーには、最初の習慣と達成時の貯金額を設定する画面を表示します。入力項目を最小限にし、すぐに利用を始められるようにしています。

### 今日の記録

ホームには登録した習慣をチェックリストとして表示します。達成した項目をタップすると即座に金額が加算され、もう一度タップすると取り消せます。同じ日に複数の習慣を記録できます。

### 貯金の可視化

ホームでは累計額、当日の増加額、継続日数をひと目で確認できます。折れ線グラフでは貯金額の推移と目標金額を重ねて表示し、積み重ねを視覚的に実感できるようにしています。

### 振り返り

カレンダーには、日ごとの達成数と貯金額を表示します。日付を選択すると、その日に達成した習慣の内訳を確認できます。

## プロダクト設計で意識したこと

- **前向きな言葉選び** — 「失敗」や「未達成」を強調せず、達成した行動に焦点を当てています。
- **操作の少なさ** — 毎日使う記録操作は、ホームから 1 タップで完了します。
- **金額の一貫性** — 記録時点の金額を履歴へ保存するため、後から習慣の設定額が変わっても過去の累計額は変化しません。
- **複数習慣への対応** — 習慣と達成記録を分離し、ユーザーが生活に合わせて自由に追加できる構造にしています。
- **モバイルファースト** — 片手で操作しやすいレイアウトと、ホーム画面へ追加できる PWA を採用しています。

## 使い方

1. 初回ログイン後、最初の習慣と達成時の貯金額を登録します。
2. 必要に応じて設定画面から習慣を追加します。
3. その日に達成した習慣をホーム画面でタップします。
4. 習慣ごとの金額が貯金へ加算されます。
5. グラフやカレンダーで、行動とお金の積み重なりを振り返ります。

このアプリが表示する金額は貯金の記録です。銀行口座への入金や決済は行いません。

## 技術的なポイント

### Server Components と Server Actions

データ取得を Server Components で行い、ブラウザへ不要な処理や認証情報を送らない構成にしています。達成記録や設定変更には Server Actions を使用し、各処理でログインユーザーを再確認しています。

### ユーザーごとのデータ分離

すべての主要テーブルに`user_id`を持たせ、Supabase の Row Level Security でも所有者を検証しています。画面や Server Actions だけに依存せず、データベース側でも別ユーザーのデータへアクセスできないようにしています。

### 履歴としての貯金額

習慣の設定金額だけを参照して累計を計算するのではなく、達成した時点の金額を`habit_records.amount`へ保存します。たとえば運動の金額を 300 円から 500 円へ変更しても、変更前の記録は 300 円のまま保持されます。

## セットアップ

### 1. Supabase プロジェクトを準備する

1. [Supabase](https://supabase.com)でプロジェクトを作成します。
2. SQL Editor で`supabase/schema.sql`を実行します。
3. Authentication > Users からログイン用ユーザーを作成します。
4. Project Settings > API から Project URL と anon key を取得します。

現在はユーザー向けのサインアップ画面を用意していないため、ユーザーは Supabase の管理画面から作成します。

既存環境を複数習慣対応へ更新する場合は、次のマイグレーションを番号順に実行してください。

```text
supabase/migrations/002_extended_settings.sql
supabase/migrations/003_daily_amount_default.sql
supabase/migrations/004_multiple_habits.sql
```

`004_multiple_habits.sql`は、既存の「続けたいこと」と達成記録を最初の習慣へ引き継ぎます。

### 2. 環境変数を設定する

```bash
cp .env.local.example .env.local
```

`.env.local`へ Supabase の接続情報を設定します。

```env
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

### 3. ローカルで起動する

```bash
npm install
npm run dev
```

[http://localhost:3000](http://localhost:3000)を開き、Supabase で作成したユーザーとしてログインします。

### 4. 品質チェック

```bash
npm run lint
npx tsc --noEmit
npm run build
```

## データモデル

- `habits` — 習慣名、達成時の貯金額、有効状態
- `habit_records` — 習慣ごとの達成日と、その時点の貯金額
- `savings_goals` — 貯金の目標名と目標金額
- `settings` — 旧バージョンとの互換設定
- `daily_records` — 旧形式の記録（移行後もデータ保全のため保持）

各テーブルでは Supabase の Row Level Security を有効にし、ログインユーザーが自分のデータだけを操作できるようにしています。
